# Tailrec Refactor Plan

## CLI Change

`tailrec <backend> [args...]` — backend (e.g. `claude`) is now a positional arg, not config.
Remove `backend` field from TailrecConfig. Remove `model` field (user selects via TUI or backend flags).

## MCP Tools (slash commands)

Exposed as MCP tools with `t.` prefix to avoid collision with backend builtins.

### /t.plan [content]
- Generate plan card structure under `cards/plans/<plan-title>/`
- Creates: `plan.md`, `design.md`, `tasks.md`
- If plan is too large or spans multiple protocols/principles, LLM splits into structured sub-cards
- Card frontmatter: `type: plan`, `title: ...`

### /t.resume
- List available plans by title, user selects
- Restore task queue state from `tasks.md` completion markers

### /t.specify [content]
- Add specification docs linked to plan card, optimize existing plan docs with new constraints

### /t.adjust [content]
- Modify task breakdown in `tasks.md` (reorder, split, merge, remove)

### /t.tasks
- Show task list with completion status
- Maintained in plan's `tasks.md` card

### /t.start
- Begin executing tasks sequentially via tailrec loop
- Insert shared principles (from plan's `design.md`) into system prompt
- System prompt instructs: "before completing, save decisions/tips to next task's input card, then call reassemble with next task title"

### /t.archive
- Move plan from `cards/plans/` to `cards/archive/plans/`
- Summarize knowledge into `cards/features/` and `cards/designs/` (ground truth cards)

## Wrapper Commands (handled directly by tailrec, no LLM call)

### /t.cost
- Show actual tailrec cost (sum of all iterations)
- Show hypothetical single-session cost: cumulative input tokens (O(n²) growth), minus assembly overhead delta
- Intercepted by PTY layer before reaching backend — pure local computation

## Task Execution Flow

```
/t.start
  → read tasks.md, find first incomplete task
  → reassemble(task_title)
  → spawn backend with appended prompt containing:
      - selected cards (collector picks from plan context)
      - instruction: "save decisions/tips to next task input card before finishing"
  → backend session runs interactively
  → claude calls reassemble({ next_input: "next task title" })
  → MCP writes signal, SIGTERM backend
  → [inter-session gap]:
      backend -p <small_model> reads previous session context
      → generates handoff summary → saves to tasks/<next_task>/input.md
  → reassemble loop picks up next task
  → collector reads input.md as context card
  → spawn fresh backend session
  → repeat until all tasks complete
```

## Card Directory Structure

```
.tailrec/cards/
├── plans/
│   └── <plan-title>/
│       ├── plan.md          # plan overview, goals
│       ├── design.md        # architectural decisions, principles (shared in prompt)
│       ├── tasks.md         # task list with completion status
│       └── tasks/
│           ├── <task1>/
│           │   ├── task.md   # task description
│           │   └── input.md  # handoff context from previous task (generated by small model)
│           └── <task2>/
│               ├── task.md
│               └── input.md
├── features/               # ground truth: feature docs (persisted knowledge)
├── designs/                # ground truth: design decisions (persisted knowledge)
└── archive/
    └── plans/              # completed plans moved here by /t.archive
```

Link resolution: `[[wikilinks]]` grep across all subdirectories, path differences are transparent.

## Reassemble Inter-Session Bridge

Between sessions (after backend exit, before next spawn):

1. Call `<backend> -p --model <small_model>` with prompt:
   - "Read the session transcript. Extract: key decisions made, tips for next task, relevant state changes."
2. Save output to `tasks/<next_task>/input.md`
3. Collector picks up `input.md` as context card for next iteration

This keeps the bridge cost minimal (small model, single call) while preserving cross-task continuity.

## Config Changes

Remove from TailrecConfig:
- `backend` (now CLI positional arg)
- `model` (user controls via backend flags or TUI)

Keep:
- `collector_model` — small model for card selection
- `bridge_model` — small model for inter-session handoff (may be same as collector_model)
- `cards_dir`
- `state_dir`
- `shared_card_sort_key`

## Refactor Scope

1. CLI: change Commander setup — `tailrec <backend>` as positional, remove model/backend config
2. MCP server: add tools (`t.plan`, `t.resume`, `t.specify`, `t.adjust`, `t.tasks`, `t.start`, `t.archive`, `t.cost`)
3. Session loop: add inter-session bridge call (small model → input.md)
4. Cards: support subdirectory loading, add `type` frontmatter field, recursive workspace scan
5. State: task completion tracking via `tasks.md` card content (not separate JSON)
6. Cost: add hypothetical cost calculation (cumulative input token simulation)
